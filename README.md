# Чашка кофе

Новый сайт сети ресторанов «Чашка кофе», который заменит `chashkacoffee.ru`.

Публичные страницы и меню разрабатываются как лёгкий SEO-ориентированный сайт; операционный контент, заявки и доступы сотрудников — как отдельная админка. Полное продуктовое описание находится в [техническом задании](./chashka-coffee-technical-spec.md).

## Принятые решения

- **Slug:** `chashka-coffee`.
- **Активные поверхности:** `website` (Astro), `webapp` (React-админка), `backend` (Bun/Hono API) и `packages/contracts` (общие DTO и валидация).
- **Отложено:** мобильное приложение; разработка ведётся на основной ветке шаблона без Expo.
- **Основные пользовательские маршруты:** список ресторанов → страница ресторана → его меню; общий пункт «Меню» → меню первой актуальной точки с назначенным меню, с переключателем ресторана внутри страницы.
- **Данные и доступы:** PostgreSQL локально через Docker Compose; сотрудники входят по ролям, а гости — по телефону и SMS через PremiumBonus. Гостевая сессия действует 7 дней.
- **Покупка кофе:** товары и варианты можно добавить в локальную корзину, оформить заказ без оплаты и выбрать самовывоз только из разрешённых в админке ресторанов. Подробности — в [docs/ONLINE_COFFEE_ORDERS.md](./docs/ONLINE_COFFEE_ORDERS.md).
- **Личный кабинет:** `/account` живёт на публичном Astro-сайте и показывает профиль, общий бонусный баланс, QR-код и историю онлайн-заказов кофе. Ресторанные чеки в неё не входят.
- **Админка:** разделы вынесены в боковую навигацию, а списки, создание и редактирование открываются на отдельных экранах. Управление командой и статистика доступны только администраторам.
- **Рабочее пространство:** админка защищает несохранённые формы, поддерживает публикацию по расписанию, глобальный поиск, рабочие очереди, массовые статусы, предпросмотр и журнал изменений. Подробности — в [docs/ADMIN_WORKSPACE.md](./docs/ADMIN_WORKSPACE.md).
- **Статистика:** публичный сайт передаёт в API обезличенные просмотры без имён, телефонов и IP-адресов. Подробности — в [docs/ANALYTICS.md](./docs/ANALYTICS.md).
- **Файлы и интеграции:** медиатека и изображения предусмотрены в архитектуре; до появления сервера используются локальные файлы. Telegram понадобится для уведомлений о заявках позднее.
- **Не входит сейчас:** приём платежей, real-time/WebSocket-функции, домен, сервер и деплой.
- **Отложено в кабинете:** регистрация новой бонусной карты и редактирование профиля.

## Структура

- `website` — публичный Astro-сайт, индексируемые страницы и SEO.
- `webapp` — закрытая React-админка для сотрудников.
- `backend` — монолитный Bun/Hono API, Prisma и фоновые задачи.
- `packages/contracts` — общие Zod-схемы и TypeScript-типы.
- `docs` — архитектурные, локальные и эксплуатационные заметки.

## Локальный запуск

Проект использует Bun `1.3.14` и Docker Desktop с Compose v2. Bun пока должен быть установлен на рабочем компьютере; PostgreSQL нативно не нужен.

```bash
bun install
docker compose up -d postgres
cp backend/.env.example backend/.env
bun run --cwd backend prisma:migrate
```

В отдельных терминалах:

```bash
bun run dev:backend
bun run dev:webapp
bun run dev:website
```

Для личного кабинета добавьте выданный PremiumBonus токен в `backend/.env` как `PREMIUMBONUS_API_TOKEN`. Токен остаётся только на бэкенде и не должен попадать в переменные `PUBLIC_*`.

Подробности по локальной БД: [docs/LOCAL_DATABASE.md](./docs/LOCAL_DATABASE.md). До подключения деплоя проект работает только локально.
