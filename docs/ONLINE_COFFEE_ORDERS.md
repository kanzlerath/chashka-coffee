# Онлайн-заказы кофе с самовывозом

Сайт принимает оплату за кофе через тестовый или боевой магазин ЮKassa. Заказы доступны только для самовывоза.

## Покупательский сценарий

1. Покупатель выбирает фасовку кофе и добавляет её в корзину.
2. На `/checkout` backend заново рассчитывает состав и сумму по актуальным данным.
3. Покупатель выбирает точку, указывает имя, телефон и обязательный e-mail для фискального чека.
4. Backend идемпотентно создаёт заказ и платёж ЮKassa. Повторный клик возвращает тот же URL оплаты, а не создаёт дубль.
5. Редирект браузера не считается подтверждением. Статус `PAID` ставится только после webhook и повторного GET-запроса платежа к API ЮKassa.
6. После возврата на `/order?token=…` сайт сам проверяет статус. Отменённый платёж можно повторить без нового заказа.

## Статусы и чеки

```text
AWAITING_PAYMENT --проверенный webhook--> PAID -> PREPARING -> READY_FOR_PICKUP -> COMPLETED
```

- Ручной перевод в `PAID` запрещён.
- Отмена заказа в админке временно запрещена, пока не реализован безопасный возврат денег и чек возврата.
- При оплате уходит первый чек: `full_prepayment`, товар, `vat_code: 1` (без НДС).
- При выдаче и переводе в `COMPLETED` backend сначала создаёт чек зачёта предоплаты: `full_payment` с расчётом `prepayment`.
- В кабинете «Чеки от ЮKassa» система налогообложения должна быть настроена как ОСНО. Код ставки НДС закреплён в серверном коде; клиент его не передаёт.

## API

- `POST /api/store/quote` — серверный расчёт корзины;
- `GET /api/store/pickup-locations` — точки самовывоза;
- `POST /api/store/orders` — идемпотентное создание заказа;
- `POST /api/store/orders/:accessToken/payment` — создание или повторная выдача redirect-платежа;
- `POST /api/payments/yookassa/webhook` — уведомления `payment.succeeded` и `payment.canceled`;
- `GET /api/store/orders/:accessToken` — приватная страница заказа;
- `GET /api/customer/orders` — история авторизованного покупателя;
- `GET /api/admin/orders` и `PUT /api/admin/orders/:id/status` — рабочая очередь.

## Настройка тестового магазина

Заполните всю группу переменных; если они пусты, API оплаты выключен:

```dotenv
YOOKASSA_SHOP_ID=<test-shop-id>
YOOKASSA_SECRET_KEY=<test-secret-key>
YOOKASSA_RETURN_URL=https://dev.chashkacoffee.ru/order
YOOKASSA_TEST_MODE=true
```

Секрет хранится только в backend env. В кабинете тестового магазина:

1. Подключите «Чеки от ЮKassa», выберите ОСНО и проверьте, что кофе оформляется «без НДС».
2. Добавьте HTTP-уведомления `payment.succeeded` и `payment.canceled` на `https://api-dev.chashkacoffee.ru/api/payments/yookassa/webhook`.
3. Проведите оплату тестовой картой и проверьте: заказ стал `PAID`, первый чек появился в истории ЮKassa, а после `COMPLETED` появился чек зачёта предоплаты.

## Webhook и восстановление статуса

- YooKassa ожидает от webhook ответ HTTP `200`. При другом ответе она повторяет доставку уведомления в течение 24 часов.
- Backend не доверяет содержимому уведомления само по себе: по `object.id` он повторно получает платёж из API YooKassa и сверяет магазин, режим тестирования, заказ, сумму, валюту и итоговый статус.
- Если платёж и чек успешны в YooKassa, а заказ остался `AWAITING_PAYMENT`, сначала проверьте точный URL webhook и историю его доставки. Возврат покупателя на сайт не заменяет webhook.
- Для восстановления уже оплаченного тестового заказа можно повторно передать уведомление с реальным идентификатором платежа. Это безопасно только как ручная диагностика: backend всё равно проверит платёж через API YooKassa.

```bash
curl --fail-with-body \
  -X POST https://api-dev.chashkacoffee.ru/api/payments/yookassa/webhook \
  -H 'Content-Type: application/json' \
  --data '{"type":"notification","event":"payment.succeeded","object":{"id":"<yookassa-payment-id>"}}'
```

Успешный ответ: `{"ok":true}`. Не передавайте в переписке `Cookie`, секрет магазина и полный приватный URL заказа с `accessToken`; для диагностики достаточно HTTP-статуса, тела ошибки и идентификатора платежа.

Перед боевым запуском нужно отдельно реализовать возвраты, чеки возврата, мониторинг статусов чеков и сверку платежей.

Документация провайдера: [HTTP-уведомления YooKassa](https://yookassa.ru/developers/using-api/webhooks).
