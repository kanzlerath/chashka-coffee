# Операционные уведомления в Telegram

Telegram используется только для внутренних оперативных сообщений. Каждая фактическая форма сайта имеет отдельное событие:

- новый онлайн-заказ кофе;
- новая заявка в кондитерскую;
- вопрос или идея из нижней формы в футере;
- обращение со страницы контактов;
- заявка на бронирование;
- заявка на банкет;
- заявка по франшизе;
- регистрация на событие;
- отклик на конкретную вакансию;
- общее обращение о работе без выбранной вакансии.

Каждый получатель хранится отдельно и подписывается только на выбранные события. Управление доступно суперадмину в разделе `/telegram` админки.

## Настройка бота

1. Создайте отдельного бота через `@BotFather`.
2. Добавьте токен и username без начального `@` в окружение backend:

```dotenv
TELEGRAM_BOT_TOKEN="<bot-token>"
TELEGRAM_BOT_USERNAME="chashka_notifications_bot"
```

3. Перезапустите backend.
4. Человек, которому нужны уведомления, открывает бота и нажимает Start.
5. Суперадмин открывает «Telegram» в админке, нажимает «Обновить список», выбирает человека и отмечает нужные события.
6. После подключения отправьте тестовое сообщение из карточки получателя.

Токен хранится только в окружении backend. Его нельзя добавлять в `PUBLIC_*`, `VITE_*`, репозиторий, скриншоты или клиентский код.

## Почему человек сначала пишет боту

Telegram-бот не может начать личный диалог сам. Админка читает недавние личные сообщения методом `getUpdates`, поэтому получатель сначала должен нажать Start или отправить боту сообщение. Username сам по себе для надёжной доставки недостаточен; после контакта сохраняется числовой `chat_id`.

Для этого бота нельзя одновременно включать webhook: Telegram считает `getUpdates` и webhook взаимоисключающими способами получения обновлений. Входящие обновления хранятся Telegram не дольше 24 часов, поэтому подключать получателя лучше сразу после нажатия Start. См. официальные описания [получения обновлений](https://core.telegram.org/bots/api#getupdates), [отправки сообщений](https://core.telegram.org/bots/api#sendmessage) и [ссылок на бота](https://core.telegram.org/api/links#bot-links).

## Поведение при ошибках

- Ошибка Telegram не отменяет успешно созданный заказ, заявку или отклик.
- В карточке получателя сохраняется последняя ошибка доставки; успешный тест или следующее успешное сообщение очищает её.
- Повторное создание заказа с тем же `idempotencyKey` не вызывает повторное уведомление.
- Удалённый или поставленный на паузу получатель больше не участвует в рассылке.

Доставка выполняется непосредственно после сохранения исходного события. Автоматической очереди повторных попыток пока нет; если для операций потребуется гарантированная доставка при длительных сбоях Telegram, следующий шаг — PostgreSQL outbox и обработчик в существующем backend worker.
