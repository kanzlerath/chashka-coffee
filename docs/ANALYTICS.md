# Статистика публичного сайта

После разрешения аналитики в cookie-баннере публичный Astro-сайт отправляет один обезличенный `page-view` при открытии страницы и запускает Яндекс.Метрику, если для сборки задан `PUBLIC_YANDEX_METRIKA_ID`. API сохраняет собственное событие в PostgreSQL, а админка показывает сводку за 7, 30 или 90 дней.

## Что собирается

- путь страницы без query-параметров;
- обезличенный UUID посетителя из `localStorage`;
- дата и время;
- тип устройства: компьютер, планшет или телефон;
- origin и path предыдущей страницы, если браузер передал referrer.

Имя, e-mail, телефон, IP-адрес и полные URL с query-параметрами не сохраняются собственной аналитикой. Состав данных Яндекс.Метрики определяется её настройками; Вебвизор в коде сайта отключён. Сбой отправки статистики не мешает открытию сайта.

До выбора пользователя ни собственный `page-view`, ни скрипт Яндекс.Метрики не запускаются. Выбор хранится локально в браузере и доступен для изменения через ссылку «Настройки cookies» в подвале. При отказе анонимный UUID собственной аналитики удаляется, а уже запущенный счётчик Метрики останавливается.

## Доступ и локальная работа

- запись просмотра: `POST /api/analytics/page-view`;
- сводка: `GET /api/admin/analytics?days=30`, только для роли `ADMIN`;
- миграция `20260720160410_add_page_views` должна быть применена к локальной и боевой базе;
- `PUBLIC_API_URL` в `website` должен указывать на доступный браузеру API. В локальной среде по умолчанию используется `http://localhost:3000`.
- `PUBLIC_YANDEX_METRIKA_ID` должен содержать только числовой ID счётчика; пустое значение оставляет интеграцию отключённой.

## Перед публичным запуском

Сейчас собственные события не удаляются автоматически. До публичного запуска нужно согласовать срок хранения и финальный текст политики конфиденциальности с ответственным за персональные данные. После этого следует добавить плановую очистку `page_views` в соответствии с этим сроком и сверить настройки хранения в Яндекс.Метрике.
